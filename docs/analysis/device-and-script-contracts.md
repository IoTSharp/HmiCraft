## 本项目应明确的脚本合同

1. 整数宽度、符号、浮点、字符串编码与所有权显式定义；不按宿主C的long宽度推断设备ABI。
2. 校验算法需固定多项式、初值、反射、末尾异或、字节序与测试向量；API名不能替代规范。
3. 延时、取消、事件调用和持续调度有预算；不能让脚本阻塞UI或串口工作。
4. 串口读写明确缓冲容量、返回长度、超时、取消和错误；不沿用缺少长度的接口设计。
5. GPIO/ADC/PWM/计数以逻辑资源名称操作；实际极性、量程、频率和错误反馈由board profile确定。
6. HMI逻辑变量与MCU物理寄存器分离，脚本不直接解引用配置中的地址字符串。
7. LVGL控件、资源句柄、页面生命周期、事件顺序和线程归属由本仓统一管理。

## 设备与协议模型

设备能力、屏幕参数、资源预算、基础固件、包/API版本、端序和协议实例分别建模。支持清单至少区分observed、implemented、host-tested与device-tested，不能把配置文件存在写成硬件通过。

Modbus RTU/TCP分别固定站号/事务号、功能码、寄存器映射、端序、异常响应、超时/重连和写入反馈。控件展示期望、已接受、已完成与实际值时应明确区别。OPC UA首版经独立网关转换，不进入MCU原生栈。

配置中的重复型号、缺失固件、错误XML和地址列异常启发输入校验：未知项明确拒绝或保留并报告，不能静默截断或选择相似名称继续交付。
