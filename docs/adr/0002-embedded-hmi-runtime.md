# ADR 0002：BASIC 驱动的 LVGL 设备执行层

- 日期：2026-10-10。
- 状态：产品路径与职责边界接受；首板/格式字段/版本/性能数值待专项验证冻结。

## 决策依据

用户明确设计器是 VB6 式拖放/属性/事件工作台，设计结果运行在 STM32 或同类 MCU 屏幕；使用 LVGL。基础框架用 IoTEmbedded 子模块，可按需要修改；日常只下载资源、动画和 BASIC 逻辑，控件库内置固件。随后确认布局也生成 BASIC、持续事件循环、工业监视采集、OPC UA 首版经网关转 Modbus/TCP，新设备闭环优先于旧 外部样本 兼容。

## 采用

1. 保留 C# / Avalonia 设计器与可编辑模型，新增目标编译/资源管线，生成 BASIC 布局及事件接线。自动生成代码与用户代码分离、稳定 ID、source map 和目标能力校验为首版合同。
2. 设备端采用纯 C HMI runtime、预编译 LVGL 控件库、本项目 BASIC 扩展。IoTEmbedded 提供解释器、平台/驱动/协议/存储；通用缺口返回子项目，双方单向依赖。
3. 将基础固件、版本化资源/脚本包、运行状态分开。资源包更新可独立于固件，新增原生能力明确要求固件升级；未知 API/目标能力/超预算在激活前拒绝。
4. BASIC 宿主持久处理有界事件，脚本可让出/取消且受预算限制。普通 LVGL 调用在 UI 任务串行执行；外设、协议、动画与业务动作有明确线程与事件边界。
5. OPC UA 保留在独立网关，屏端消费 Modbus/TCP 映射。旧 C 宏、旧工程和旧触摸屏输出独立后置。

## 取舍与未采用路径

不采用“每次布局修改都生成 C 并重刷基础固件”作为常规发布路径，因为用户选择了资源/脚本更新。也不默认再实现一个独立二进制场景解释器，因为布局创建已经由生成 BASIC 承担。后续可增加目标优化，但不得破坏明确的生成/事件合同。

LVGL、BASIC 和协议共存会占用可观内存；现 IoTEmbedded 两个 4KiB EEPROM 脚本槽和一次启动执行接口不足以承载该模型。需要存储、事件/扩展、资源预算、显示和目标平台改进；引入子模块不等于直接可运行。

P4 主选/H7 备选是基于本轮资料的硬件建议，不是已经批准采购或完成性能验收。准确设备、框架/LVGL版本、接口电气要求和资源上限在首板阶段冻结。
