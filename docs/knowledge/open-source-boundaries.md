# 开源与商业边界

状态：规划基线。用户要求将讨论结论纳入当前仓库；本文件定义后续实现和发行的分区，不自动授予新许可证。许可组合在 GOV-04 完成文件清单后定稿。

## 开放的基础平台

| 内容 | 所属项目 | 规划 |
|---|---|---|
| 工程/包格式、BASIC HMI API、board profile、部署及扩展接口 | 当前项目 | 公开规范、自测语料和诊断语义 |
| 设备 runtime、LVGL 封装、BASIC 绑定、事件/变量/资源、加载/恢复 | 当前项目 | 开源；runtime/SDK 拟 MIT |
| 社区设计器、工程模型、生成器、基础模拟与部署 | 当前项目 | 开源；社区实现拟 MPL-2.0 |
| 通用 BSP、输入/显示/IO/协议、存储、解释器内核 | IoTEmbedded | 遵守现有许可；通用改进留子项目维护 |
| 示例、生成模板、基础控件和公共扩展 SDK | 对应实现项目 | 以自有或获授权材料开放；模板/示例拟 MIT |

社区版验收闭环：编辑 → 生成 BASIC/资源 → 模拟 → 支持设备运行 → 基础外设/协议 → 更新与恢复。基础保存/生成/下装、错误诊断、脚本预算与恢复不作为人为付费障碍。目标设备本身的内存/性能限制必须真实执行。

## 独立管理的商业和保密内容

| 内容 | 管理方式 | 与开源核心的边界 |
|---|---|---|
| 高级调试 UI、性能分析、工程合并、批量交付工具 | 可独立商业模块 | 公共诊断接口与基础工具可用；独立模块不得掩盖已有覆盖代码义务 |
| 企业协作、批量生产/运维工作流、托管服务 | 可商业软件或服务 | 不作为离线设计和基础设备运行的强制依赖 |
| 量产 PCB/Gerber、工装、采购价、供应链和制造资料 | 非公开资料；设计授权另约 | 公开客户接入所需电气/机械/通信规格；是否开放参考硬件另定 |
| 客户工艺、配方、脚本、页面、算法和专属集成 | 按合同保密、交付和约定权属 | 不自动进入公共示例或框架 |
| 签名私钥、凭据、客户现场数据 | 专用受控存储 | 不进入源码、示例和公开回执 |

不为尚未实现的 Pro 创建占位收费系统。当前仓库只放自有公共平台代码、规划及可分发文档；真正出现商业模块或客户项目时，先确定独立仓库/制品和依赖合同，再放入代码。私有 Git 仓库和 `.gitignore` 都不能代替文件级分区及发行检查。

## 许可定稿交付

GOV-04 应提交一份可审阅的文件/目录清单：权利人、第三方来源及固定版本、采用许可、版权/NOTICE、是否进入源码包/固件/安装包、生成模板和用户输出的声明。当前 MIT/MPL-2.0 是方案，不能直接给全仓加一个 MIT 文件覆盖所有内容。

通用底层、平台 UI、独立商业模块、用户生成内容分别处理。用户自有内容不因使用设计器而自动归平台所有；客户定制的权属在合同约定。正式分发义务按最终选择的许可及代码组合复核，研究依据保留于 [商业研究备忘](../design/product-and-business-proposal.md)。

## OEM 和定制约束

第三方应能依据开放接口自行适配兼容设备；不能在许可允许后再用强制官方激活把基础运行封闭。官方品牌/认证、量产设计资料、服务响应和硬件质保可另行约定。兼容自测与官方认证分别记录，付费不自动等于已通过认证。

定制时先划分平台既有代码、本次通用改进、客户专属成果和第三方组件；通用修复默认按所属项目维护，客户专属内容不回流。独占/买断须明确可授予权利，不对已公开或无权独占的内容作出排他承诺。具体交付模板属于 BIZ-05。
